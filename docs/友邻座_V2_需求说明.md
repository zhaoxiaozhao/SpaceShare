# 友邻座 V2 产品需求说明

> 产品定位：围绕图书馆及公共学习空间打造的学习生活服务平台。  
> 核心理念：**让每一次去图书馆，都更有价值。**  
> 核心增长模型：**座位刚需拉新 → 学习记录留存 → 周报/排行激励 → 内容分享传播 → 图书馆生态 → 商户与广告商业化。**

## 一、产品定位

「友邻座」不再只是共享座位工具，而是**图书馆学习生活平台**。

围绕“去图书馆学习”这一核心场景，提供：

- 座位信息分享与线下接续
- 求座与接续申请
- 学习计时与学习记录
- 学习目标、周报、月报
- 学习排行榜与成就
- 知识/学习卡片分享
- 图书馆信息服务
- 图书推荐
- 周边商户服务
- 流量主、商户广告、打赏等商业化能力

核心原则：

1. 座位共享免费，不进行用户之间的座位交易。
2. 不提供用户之间的在线聊天。
3. 座位接续以线下实际交接为准。
4. 平台不替代图书馆官方座位管理系统。
5. 用户发布的信息必须真实、合法。
6. 个人信息遵循最小必要原则。
7. 内容功能必须具备举报、删除和违规处理机制。

## 二、用户与核心场景

### 核心用户

- 图书馆自习用户
- 学生
- 考研/考公用户
- 英语学习者
- 程序员和技术人员
- 论文/科研人员
- 长期学习人群

### 核心场景

**找座：**没有座位 → 查看可接续座位 → 申请 → 线下交接。

**分享：**准备离开 → 发布座位 → 他人申请 → 线下交接。

**学习：**进入图书馆 → 开始计时 → 学习 → 结束 → 自动生成统计。

**成长：**学习记录 → 周报/月报 → 排行榜 → 成就 → 分享。

**内容：**记录今日所学 → 生成学习卡片 → 发现热门知识。

## 七、线下接续机制

### 流程

```text
A发布离开信息
    ↓
B发现可接续座位
    ↓
B申请接续
    ↓
生成短期有效接续码
    ↓
双方线下见面
    ↓
A离开
    ↓
B实际接续
    ↓
完成接续
```

平台只负责**信息匹配和流程辅助**，不锁定实体座位。

接续码示例：

```text
接续码：A7K3
有效期：15:50～16:10
```

平台不保证：

- 用户一定按时离开
- 座位一定存在
- 图书馆允许座位转交
- 接续一定成功

## 八、防黄牛与信用机制

- 出售座位

后期建立用户信用体系：

- 分享成功率

- 爽约次数
- 虚假发布次数
- 举报记录

信用体系用于防滥用，不制造过度惩罚。

## 二十五、产品边界

友邻座不是：

- 图书馆官方系统
- 图书馆实体座位管理系统
- 座位交易平台
- 在线支付平台
- 社交聊天软件
- 大型开放社区

友邻座是：

> **围绕图书馆学习场景，提供座位信息、学习记录、学习成长和学习生活服务的平台。**

## 二十九、给开发 Agent 的执行原则

1. 先完成 P0，不提前实现复杂商业功能。
2. 所有业务模块保持清晰边界。
3. 座位状态必须有明确状态机。
4. 学习记录必须可追溯。
5. 排行榜必须考虑刷时长。
6. 用户内容必须具备举报和审核接口。
7. 用户信息遵循最小化原则。
8. 不实现私信和聊天。
9. 不实现用户间金钱交易。
10. 所有页面考虑小程序分享入口。
11. 后端 API 预留版本管理能力。
12. 管理后台与小程序业务权限隔离。
13. MVP 优先保证稳定性和数据准确性。
14. 不为了“生态”过早堆砌功能。
15. 每新增功能都必须回答：是否提升拉新、留存、活跃或商业价值。
