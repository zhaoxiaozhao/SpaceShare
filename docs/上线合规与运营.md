# 公益共享座位平台——上线合规与运营说明

> 文档定位：用于指导项目从开发阶段进入微信小程序正式上线阶段。
>
> 核心原则：**免费共享、免费预约、不售座、不炒座、不冒充场馆官方。**
>
> 本文是产品与工程实施参考，不替代律师、税务顾问或微信平台最终审核结论。涉及主体登记、支付、广告、备案、个人信息处理等事项，应以项目实际所在地及微信/监管平台当前规则为准。

---

# 1. 项目定位

## 1.1 对外定位

建议统一描述为：

> 公共学习空间座位共享与预约平台。

第一阶段重点服务：

- 公共图书馆
- 高校图书馆
- 阅览室
- 公共自习空间

未来扩展：

- 学习空间
- 共享办公
- 公共会议空间
- 社区公共空间

## 1.2 核心业务

用户可以：

1. 查看公共学习空间
2. 查看其他用户主动分享的座位
3. 免费预约未来时间段
4. 到达后确认使用
5. 分享自己未来的空闲时间
6. 通过平台规则进行座位交接

平台不提供：

- 座位买卖
- 座位租赁
- 座位竞价
- 座位收费
- 有偿转让
- 站内聊天

# 2. 主体选择

## 2.1 首期推荐

推荐：

> **个体工商户**

适合当前阶段：

- 个人开发
- 低成本启动
- 小程序正式运营
- 广告
- 商家合作
- 项目支持
- 微信支付

## 2.2 什么时候升级有限公司

出现以下情况时再考虑：

- 有合伙人
- 招聘员工
- 融资
- 大型商业合同
- 图书馆/学校正式合作
- 全国城市运营
- 稳定广告收入
- 商家规模化入驻

---

# 3. 主体经营范围

注册主体时，应根据所在地市场监管部门实际目录选择与业务相匹配的范围。

优先考虑覆盖：

- 软件开发
- 软件销售
- 信息技术咨询服务
- 信息系统运行维护服务
- 互联网数据服务
- 广告设计/代理/发布等

不要为了业务看起来完整而盲目增加需要额外许可的行业范围。

最终经营范围以登记机关实际核准结果为准。

# 5. 小程序类目

## 5.1 产品描述

建议使用：

> 公共学习空间座位共享与预约服务。

避免：

> 某某图书馆官方预约平台

除非取得对应场馆正式授权。

## 5.2 类目选择原则

开发阶段不要自行假设某个固定类目一定可以通过审核。

正式提交前：

1. 查看微信公众平台当前可选服务类目
2. 根据实际功能选择最接近的类目
3. 如存在多个候选，优先选择与“公共信息服务/生活服务/预约服务”实际业务最匹配的类目
4. 对支付、广告、内容发布等附加能力分别确认准入要求
5. 保留审核截图和平台反馈

---

# 6. 非官方场馆原则

平台必须明确：

> 本平台为第三方座位共享服务，不代表相关图书馆、学校或公共场馆的官方立场。

除非获得正式授权，不得使用：

- “官方”
- “指定”
- “唯一”
- “官方预约”
- “官方座位系统”

等容易造成误认的宣传语。

## 6.1 场馆页面建议展示

```text
场馆名称
地址
开放时间
座位信息
用户共享座位
```

并增加：

> 场馆开放时间、现场管理规则及座位使用规定，以场馆实际公告为准。

# 7. 座位数据来源

这是平台长期运营的重要合规边界。

## 7.1 第一阶段推荐

采用：

> 用户贡献 + 平台审核

例如：

```text
用户进入场馆
 ↓
发现A区32号座位
 ↓
提交座位信息
 ↓
平台审核
 ↓
进入座位数据库
```

## 7.2 不建议第一阶段

未经确认大量爬取：

- 室内座位地图
- 内部座位编号
- 非公开场馆数据
- 内部管理系统数据

## 7.3 官方合作

如果未来与图书馆正式合作，可以建立：

> 场馆官方数据接口 / 数据授权

然后切换为：

```text
官方数据
 +
用户共享数据
```

# 8. 用户协议

正式上线前必须准备《用户服务协议》。

建议包含：

## 8.1 平台性质

平台提供：

> 座位信息展示、共享和免费预约工具。

平台不拥有任何实体座位。

## 8.2 用户责任

用户必须：

- 遵守场馆规定
- 如实发布座位信息
- 不恶意占座
- 不出售座位
- 不发布虚假信息
- 不骚扰其他用户

## 8.3 平台责任边界

平台不保证：

- 实体座位一定存在
- 用户一定按预约到场
- 场馆一定允许共享
- 场馆一定允许使用某个座位
- 用户之间线下行为不存在风险

平台应提供：

- 举报
- 风控
- 信用
- 账号处罚
- 信息纠错

- 删除方式
- 注销方式
- 第三方服务
- 数据安全
- 用户权利
- 联系方式

# 10. 个人信息最小化

## 10.1 建议收集

必要：

- 微信用户标识
- 预约记录
- 座位分享记录
- 账号状态

按功能需要：

- 昵称
- 头像
- 手机号
- 定位
- 联系方式

## 10.2 不应主动收集

除非有明确必要性：

- 身份证号码
- 通讯录
- 相册全部内容
- 精确长期轨迹
- 与座位服务无关的个人信息

# 11. 定位权限

定位属于高敏感度使用场景，应采用最小化设计。

推荐：

```text
用户打开附近图书馆
        ↓
请求定位
        ↓
用户允许 → 显示附近场馆
用户拒绝 → 手动选择城市
```

不能因为拒绝非必要定位而让用户完全无法使用基本功能。

## 11.1 到达确认

建议：

```text
预约开始
 ↓
用户点击“确认到达”
 ↓
获取当前位置
 ↓
判断是否位于场馆允许范围
 ↓
确认到达
```

定位只用于必要的到达校验，不向其他用户展示精确坐标。

---

# 12. 座位二维码

未来推荐增加：

> 座位二维码 / 场馆二维码。

使用：

```text
扫描二维码
 ↓
识别场馆/楼层/座位
 ↓
确认到达
```

优点：

- 减少对定位的依赖
- 提高到达真实性
- 降低GPS漂移
- 提升用户体验

二维码不能替代风控。

---

# 13. 微信登录

第一版：

> 微信登录即可创建账号。

不要强制用户一开始提供手机号。

手机号可作为后续：

- 风控
- 联系方式
- 账号安全
- 实名相关功能

的增强能力。

---

# 14. 联系方式

平台不提供站内聊天。

联系方式采用：

> 预约成功 + 分享者主动授权。

例如：

```text
分享者：
允许预约者查看联系方式

        ↓

预约成功

        ↓

预约者：
查看联系方式
```

预约结束后：

> 自动隐藏联系方式。

禁止：

- 在公开备注发布微信号
- 发布手机号
- 发布二维码进行商业交易
- 利用平台进行骚扰

# 16. 反黄牛

这是平台核心风控。

## 16.1 基础规则

默认：

- 一个用户同时一个有效预约
- 限制每日预约次数
- 限制提前预约时间
- 到场确认
- 爽约扣信用
- 频繁取消限流
- 热门座位动态限流

## 16.2 风险行为

检测：

- 高频预约
- 高频取消
- 高频爽约
- 多账号关联
- 异常设备
- 异常IP
- 大量抢热门座位
- 座位交易
- 虚假座位
- 恶意举报

---

# 17. 信用体系

初始：

```text
100分
```

建议：

| 行为 | 分值 |
|---|---:|
| 正常到达 | +1 |
| 正常完成 | +1 |
| 提前合理取消 | 0 |
| 爽约 | -5 |
| 虚假座位 | -10 |
| 恶意占座 | -10 |
| 座位交易 | -20 |
| 恶意举报 | -10 |

所有规则必须后台可配置。

不要把信用分设计成付费可以购买。

# 18. 支持项目/赞助

产品文案建议：

> 支持项目

而不是：

> 购买座位
> 
> 购买权益
> 
> 打赏后优先预约

## 18.1 支持金额

例如：

```text
¥3
¥6
¥10
¥20
自定义
```

## 18.2 用途

明确说明：

- 服务器
- CDN
- 数据存储
- 内容审核
- 运维
- 持续开发

## 18.3 核心原则

支持项目与预约完全解耦：

```text
支持 ¥10
    ↓
不增加信用
不增加预约次数
不提高优先级
不解锁热门座位
不获取特殊座位
```

具体支付业务类型、页面文案和支付能力应以上线时微信支付商户平台审核结果为准。

- 虚假广告
- 色情内容

# 29. 冷启动策略

- 分享次数
- 分享小时数
- 帮助人数

可以获得：

- 勋章
- 公益等级
- 荣誉展示

但不能兑换预约优先权。

# 36. 产品宣传禁区

禁止宣传：

- 买座位
- 抢座神器
- 花钱优先抢座
- 内部座位
- 官方座位
- 稳定保证有座
- 付费保座
- 转卖座位

推荐宣传：

> 免费共享空闲座位。

> 离开时，把座位留给下一个人。

> 让公共座位流动起来。

# 40. Agent开发约束

交给其他Agent开发时必须遵守：

## 40.1 不得改变业务定位

不能把项目改成：

> 座位交易平台。

## 40.2 不得添加付费座位

任何：

```text
seat_price
seat_order
seat_payment
```

都不属于核心业务。

## 40.3 支持项目独立

```text
SupportOrder
```

不得影响：

```text
Reservation
Credit
Risk
```

## 40.4 不做站内聊天

联系方式采用：

> 预约成功 + 用户主动授权。

## 40.5 不收集非必要信息

特别是：

- 精确位置
- 通讯录
- 身份证
- 长期轨迹

## 40.6 所有处罚可审计

管理员操作必须进入：

```text
AuditLog
```

## 40.7 所有核心规则配置化

包括：

- 最大预约数量
- 最大提前时间
- 到达宽限时间
- 信用扣分
- 风控阈值
- 候补时间

# 43. 最终产品原则

始终坚持：

> **不卖座、不炒座、不占座。**

> **用户分享空闲时间，其他用户免费接力使用。**

> **平台负责信息撮合、预约、信用和风控。**

> **场馆现场规则优先。**

> **用户支持项目，但不能购买特权。**

> **商业化来自广告和商家，而不是座位本身。**

# 45. 结论

这个项目最重要的不是“把小程序做出来”，而是建立一个：

> **合法、免费、可信、可持续运营的公共座位共享网络。**

第一阶段应优先验证：

```text
用户愿不愿意分享
        ↓
用户愿不愿意预约
        ↓
用户是否真实到场
        ↓
用户是否再次分享
        ↓
网络是否形成正循环
```

只有这个闭环成立，再投入大量精力做：

- 广告
- 商家
- 城市扩张
- 官方场馆合作
- 高级风控

这样资金和开发资源的使用效率最高。
